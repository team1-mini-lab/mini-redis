# 테스트

[← README로 돌아가기](../../README.md)

```bash
python -m unittest -v
```

| 파일 | 확인하는 것 |
| --- | --- |
| `test_api.py` | 저장 → 조회 → 삭제 → 404, 없는 키 삭제, 덮어쓰기, 여러 키 독립, 응답 모양 |
| `test_concurrent_http.py` | 실제 HTTP 서버에 여러 클라이언트가 동시에 요청해도 유실·500 없음, 같은 키 삭제는 한 번만 `true` |
| `test_edge_cases.py` | ttl 다시 주면 연장, 만료 뒤 ttl 없이 저장하면 영구, 아주 작은 ttl, 같은 키가 쿼리에 두 번, 특이한 키, 크기 제한 없음 |
| `test_hashtable.py` | 충돌 체인의 앞·중간·끝 삭제, FNV-1a 공식 값, 0.75 경계 확장, 키 10만 개 |
| `test_expiry.py` | 가짜 시계로 만료 경계(정확히 그 시각), 덮어쓰면 만료 초기화, 확장 후에도 만료 유지 |
| `test_incr.py` | 스레드 8개 × 1,000번 `incr`해도 정확히 8,000, 비교로 `get`→`set`은 끼어들면 하나가 사라짐, 없는 키는 0부터, 만료 유지, 정수가 아니면 거절, `/incr`·`/decr` 응답과 400 |
| `test_lock.py` | 스레드 8개 × 2,000개 동시 저장에 유실 없음, 만료 확인과 삭제 사이에 `set`이 끼어들지 못함 |
| `test_validation.py` | 입력 검증 규칙, 처음 서버 틀을 만들었을 때 찾은 빈틈 3개(키 없이 저장하면 500, `value`가 `null`이어도 저장됨, 조회 때 키가 없으면 HTML로 400)가 모두 JSON 400으로 막혔는지, 없는 주소·틀린 메서드에 JSON 404·405 |
| `test_demo.py` | 캐시 어사이드, 무효화(DB 먼저 고치고 캐시 삭제), 서버 두 대에서 가격과 로그인 세션, 실제 포트에 띄운 mini-redis에 HTTP로 붙는 경로, 캐시가 죽거나 응답이 없어도 DB로 응답, 무효화를 놓쳐도 TTL이 지나면 맞아짐, 세션 만료, 잘못된 가격·로그인 입력 |

`test_demo.py`를 만든 과정(처음 14개, 검토 뒤 추가한 8개)과, 코드를 일부러 망가뜨려 테스트가 잡아내는지 확인한 변이 검사 결과는 [docs/eungi/TEST_RECORD.md](../eungi/TEST_RECORD.md)에 있습니다.
