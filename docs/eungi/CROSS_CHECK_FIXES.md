# 교차 검증 뒤 고친 것

기준 구현을 고를 때 이현지가 세 사람의 서버에 같은 요청 23개를 보내 비교했습니다(hnjee 브랜치의 STEP7.md). 그때 내 구현(커밋 `e2831c0`)에서 빈틈이 나왔고, 기준 구현으로 고르지 않은 뒤에도 원인을 이해하고 고쳐 두었습니다.

| 빈틈 | 그때 결과 | 원인 | 고친 방법 | 지금 결과 |
| --- | --- | --- | --- | --- |
| 아주 큰 정수 `ttl` (`10**400`) | **500** | `math.isfinite()`가 정수를 소수로 바꾸다 `OverflowError` | `math.isfinite()` 대신 범위 비교 `0 < ttl <= 10년`. 정수 그대로 비교되고 NaN·무한대도 걸러짐 | 400 |
| 오타 난 칸 (`"ttI": 5`) | 200, 만료 없이 영원히 저장 | 모르는 칸을 확인하지 않음 | `key`, `value`, `ttl` 말고 다른 칸이 오면 400 | 400 |
| `Content-Type` 없이 보낸 본문 | 200 | `get_json(force=True)`가 헤더를 무시함 | `force=True`를 뺌. JSON이라고 밝힌 요청만 받음 | 400 |
| 아주 긴 `ttl` (`1e300`) | 200 | 상한이 없음 | 상한 10년 (기준 구현과 같은 값) | 400 |

테스트는 `tests/test_api.py`의 `test_gaps_found_by_cross_check`, `test_ttl_boundaries_still_work`입니다. 고치기 전 코드로 돌리면 두 테스트가 실패하고, 고친 뒤에는 통과합니다.

```bash
python -m pytest -v tests/test_api.py
```

**배운 것.** 각자의 테스트는 각자가 생각한 경우만 확인합니다. 내 테스트 7개는 모두 통과했지만, 다른 사람이 만든 같은 요청 23개를 보내자 내가 생각하지 못한 입력에서 빈틈이 드러났습니다. 이 경험 때문에 8·9단계에서는 설계 결정마다 테스트를 연결하고, 코드를 일부러 망가뜨려 테스트가 잡아내는지까지 확인했습니다.
