# 개인 결정 기록 (eungi)

구현하면서 제가 정한 것을 적습니다. 팀 설계 문서([DESIGN.md](../DESIGN.md))의 결정 기록에는 합의된 내용만 들어가므로, "팀 결정 필요"가 "예"인 줄만 팀 회의에 가져갑니다.

- 단계 번호는 DESIGN.md 3번의 개발 단계와 같습니다.
- 상태는 "확정"(정함)과 "미결정"(아직 고민 중) 두 가지입니다.
- 결정을 바꿀 때는 그 줄을 고치고, 이유 칸에 "(변경: 이전에는 ...)"을 덧붙입니다.

| 2 | 충돌 처리는 체이닝, 각 항목에 키와 값을 함께 저장 | 구현과 설명이 단순함. 같은 칸에서 키로 찾아야 함 | 아니오 (DESIGN.md와 같음) |
| 2 | 저장소 안에서 `dict`/`set`은 쓰지 않음. 칸 배열은 `list`, 체인은 `Node(key, value, next)` 연결 리스트 | 해시 테이블 직접 구현이 과제 요구사항. 연결 리스트로 체이닝 원리를 직접 다룸, 값 수정은 `node.value`로 바로, 삭제는 화살표만 바꾸면 됨 (변경: 이전에는 체인도 `list`에 `[키, 값]`) | 예 (알림: DESIGN.md 결정 2번 제안은 리스트. 접점은 그대로) |
| 2 | 새 노드는 체인 **맨 앞**에 삽입 | 첫 노드만 바꾸면 돼서 한 번에 끝남. 체인 안 순서는 조회 결과에 영향 없음 | 아니오 |
| 2 | 항목 수를 `self.size`로 직접 셈 (새 키일 때 +1, 실제 삭제 때 −1) | 3단계 부하율 계산에 필요 | 아니오 |
| 2 | 체이닝 검증은 `Store(capacity=1)`로 모든 키를 한 칸에 몰아 테스트 | 충돌을 확실하게 만들어 저장·조회·덮어쓰기·가운데 삭제를 확인 | 아니오 |
